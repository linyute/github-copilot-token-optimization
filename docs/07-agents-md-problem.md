# 2.6 常駐上下文的問題 — 少即是多

[← 回到指南](index.md)

---

> `AGENTS.md`、`.github/copilot-instructions.md` 與 `CLAUDE.md` 的範圍與工具支援各不相同。一個儲存庫可以同時使用多種，但每一種在被工具載入時都會增加上下文。以下研究測試的是 `AGENTS.md`。請以它作為修剪其他常駐檔案的參考，而非將其視為這些格式的獨立基準測試。壓縮範例請參閱[第 2.3 部分](04-context-management.md)。

## 2.6.1 研究：上下文檔案常常適得其反

詳盡的上下文檔案是否能提升代理程式的表現？以下研究檢驗了這個假設。

**蘇黎世聯邦理工學院的研究（Gloaguen 等人，AGENTBENCH，2026 年 2 月）以大規模方式測試了這個問題：涵蓋 12 個儲存庫的 138 項任務、4 種不同的程式碼代理程式。** 結果如下：

| 發現 | 資料 |
|---------|------|
| 由 LLM 產生的上下文檔案會損害表現 | 在 8 種實驗設定中有 5 種表現下降 |
| 平均正確率變化 | AGENTBENCH 上為 **−2%** |
| 使用 LLM 產生的上下文時成本增加 | 多消耗 **20-23%** 的 token |
| GPT-5.2 推理額外負擔 | 有上下文檔案時多出 **22%** 的推理 token |

在這些設定中，產生的上下文檔案增加了成本，卻沒有提升平均正確率。

## 2.6.2 人工撰寫的檔案：頂多只有些許助益

人工撰寫的上下文檔案顯示出小幅且不一致的平均改善：

| 模型 | 人工撰寫上下文檔案的效果 |
|-------|--------------------------------------|
| 各模型平均 | 約 4% 的改善（不一致） |
| Claude Code | 使用人工撰寫的上下文反而**更差** |
| 檔案探索率 | 有無上下文檔案皆相同 |

## 2.6.3 為什麼更多上下文反而有害

有四種機制可以幫助解釋這些發現：

**1. 冗餘。** 上下文檔案可能重複 `package.json`、import 陳述式與目錄結構中本來就能取得的事實。代理程式等於把相同的資訊處理了兩次。

**2. 注意力。** Liu 等人，〈Lost in the Middle〉（2023）描述了模型對長上下文中間部分資訊的運用較弱。若重要規則被埋在 200 行的 `AGENTS.md` 中，可能更難被記住。

**3. 錨定效應。** 代理程式可能過度遵循已過時的指引。在 `AGENTS.md` 中提到某個工具，會使該工具的使用率提高 **1.6 倍**，即使另一個工具更適合該任務也是如此。

**4. 訊噪比。** 像「此專案使用 TypeScript」這類例行事實，在 `tsconfig.json` 已經說明的情況下幾乎沒有價值。它們還可能掩蓋代理程式無法自行發現的警示，例如一項待處理的稽核使得不能重構驗證功能。

## 2.6.4 反面觀點：效率與正確性

Lulla 等人（2026 年 1 月）發現，人工撰寫的 `AGENTS.md` 使**執行時間縮短 29%**、**輸出 token 減少 17%**。他們衡量的是效率，而非正確性。

請將這兩種結果分開看待。更快的導覽很有用，但並不能證明答案正確。

## 2.6.5 上下文檔案實際上該放什麼

Addy Osmani 的篩選原則（Google，2026）：

> **「代理程式能否透過閱讀您的程式碼自行發現這件事？如果可以，就刪掉它。」**

通過此篩選的內容：

| 保留 | 刪除 |
|------|--------|
| 「使用 `uv` 而非 `pip`」 | 「這是一個 Python 專案」 |
| 「執行測試時使用 `--no-cache`」 | 「測試位於 `tests/` 目錄」 |
| 「不要重構 auth 模組」 | 「我們使用 JWT 進行驗證」 |
| 「部署需要 VPN 連線」 | 「main 分支受到保護」 |
| 「資料庫遷移必須依序執行」 | 「我們使用 PostgreSQL」 |

保留專案特有的陷阱：看起來很普通、卻會造成錯誤的事項。移除代理程式能從程式碼中發現的事實。

## 2.6.6 理想做法：把它當成錯誤追蹤器

```text
從幾乎空白的檔案開始。
代理程式在某處出錯 → 加上一行。
根本原因修正後 → 刪除那一行。
```

當反覆出現的錯誤需要時，才加入指引。當根本問題解決後，就移除該指引。

## 2.6.7 套用篩選原則

回應偏好請使用[入門範本](10-practical-setup.md#step-1-set-a-concise-response-default)，然後只加入專案特有的陷阱。全域、限定範圍與隨選的放置方式，請遵循[上下文管理](04-context-management.md#scoping-guidance)。
