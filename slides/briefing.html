清楚瞭解您付費的項目

輸入

系統提示詞、說明、檔案、歷史紀錄、工具 Schema 及您的提示詞。

輸出

回應、推理與工具呼叫。通常是成本最高的 Token 類型。

快取輸入

穩定的請求前綴可以以更低的有效成本重複使用。

Agent 迴圈

每次讀取、命令、重試與重做步驟都會使成本發揮複利效果。

優先順序堆疊

  1. 限制輸出。 停止為您不需要的內文付費。
  2. 縮減 Context。 保持常駐說明與檔案聚焦。
  3. 減少工具開銷。 僅載入所需的 MCP 工具並壓縮命令輸出。
  4. 避免重做。 選擇正確的模式、模型、計畫與驗證。

1. 預設限制輸出

僅限程式碼。除非要求否則不提供解釋。

對程式碼任務、審查與摘要使用簡短、明確的格式。輸出控制會在每次互動中發揮複利效果。

當任務需要時，請勿壓縮推理或依據。

2. 壓縮常駐說明

保留

專案地雷區、命令、命名、架構規則、輸出限制。

移除

樣板、探索事實、重複規則、偶爾使用的工作流程檢查清單。

.github/copilot-instructions.md 中的每個 Token 都會被重複計費。請將罕見的指導方針放在限定範圍或隨選檔案中。

3. 精準鎖定 Context

  • 關閉不相關的編輯器分頁，並避免附加大型檔案。
  • 使用 applyTo 說明檔案來設定特定路徑的規則。
  • 在 AI 作業前將豐富輸入轉換為 Markdown。
  • 僅傳送相關計畫與檔案，而非整個專案歷史紀錄。

4. 保護快取前綴

對於單一長任務，請保持以下內容穩定：

{ model, reasoning effort, loaded skills, MCP/tool set, agent/profile }

變更管道或控制架構可能會失去快取前綴的節省效益。請帶著精簡的交接開啟新的聊天。

5. 使用具備能力的最輕量模式

Ask

問題、解釋、決策。不需要工具。

Edit

已知檔案與意圖的具體變更。

Agent

需要探索、命令與驗證的多檔案工作。

對於 Ask 模式即可回答的問題，請勿使用 Agent 模式。

6. 按任務路由模型

  • 日常工作優先選擇 Auto。
  • 查詢、語法、小型機械式修改使用輕量級模型。
  • 規劃、架構與困難除錯使用強大推理模型。
  • 寫下困難決策後進入執行管道。

在長工作階段開始前選擇推理努力度。請勿在對話串中途提高推理努力度。

7. 先規劃，然後在新工作階段中執行

擷取驗收條件、可能檔案、風險與驗證。僅攜帶該交接內容開始執行。

8. 保持 MCP 基準簡短

  • 每個啟用的 MCP 工具 Schema 都會在 Agent Context 中重複。
  • 停用此儲存庫或任務不需要的伺服器與擴充套件。
  • 對重複的工作流程使用乾淨的設定檔或專用的 Agent。
  • 在 Copilot CLI 中執行 /context 以檢視已載入的內容。

9. 一次性壓縮 Shell 輸出

RTK

針對常見開發者命令輸出的編譯預設值。

snip

YAML 管道與本地節省追蹤。

每個命令路徑選擇一個篩選層。預設情況下請勿同時堆疊兩者。

10. 重複使用程式碼庫定向

Graphify 對大型儲存庫進行一次性對映，之後 Agent 即可查詢結構，而非重複讀取大量檔案集。

graphify query "where is auth middleware?"
graphify path "Router" "Database"

最適合大型儲存庫與重複的 Agent 工作階段。對於小型、一次性的變更可跳過。

11. 使 Token 使用量可視化

工作階段內

使用 /context 檢查 Copilot CLI Context 壓力與已載入工具。

跨工作階段

Tokentop 顯示本地即時 Token、成本、消耗率與預算警報。

可視化能發現浪費。它本身不會壓縮 Context。

12. 設定穩定的工作階段控制架構

Model + effort + mode + agent + skills + MCP tools + output filter + repo instructions

在長時間工作前選擇它。若任務需要不同的控制架構，請建立全新的工作階段，而非修改長逐字稿。

13. 完成前進行驗證

  1. 列出驗收條件。
  2. 執行針對性的測試、建構或檢查。
  3. 報告依據，而非通用的「完成」。

微小的驗證成本可避免日後開啟新的除錯或審查工作階段。

14. 採納並持續保持

第 1 週

限制輸出。修剪儲存庫說明。

第 2 週

審慎路由 Ask、Edit 與 Agent。

第 3 週

稽核 MCP 工具與命令輸出。

第 4 週

先規劃的工作流程、快取穩定性與用量審查。

每個任務：限制輸出、精準 Context、選擇控制架構、規劃並驗證。
