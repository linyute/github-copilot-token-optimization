1. 從精簡輸出開始

回答要精簡。保留足以採取行動的證據。

比較預設、精簡與 Caveman 的總成本與正確性。證據與協定。

2. 壓縮常駐指示

保留

專案陷阱、必要命令、命名、架構規則、輸出限制。

移除

樣板文字、程式碼中已可見的事實、重複的規則、偶爾才用到的檢查清單。

載入的指示會在後續每一輪增加輸入。將特定路徑的規則放入限定範圍的檔案，偶爾才需要的指引則改為按需載入。

3. 有意識地鎖定上下文

  • 關閉不相關的編輯器分頁，避免附加範圍過廣的檔案。
  • 使用 applyTo 指示檔案來設定特定路徑的規則。
  • 在進行 AI 工作前，先將豐富格式的輸入轉換為 Markdown。
  • 傳送相關的計畫與檔案，而不是整個專案歷史。

4. 保護快取前綴

執行單一長任務時，請保持下列項目穩定：

{ 模型, 推理強度, 已載入的技能, MCP/工具集, Agent/設定檔 }

變更這些設定可能會失去快取節省的效益。需要變更時，請以簡短的交接內容開啟新的對話。

5. 使用夠用的最小模式

Ask

問題、說明、決策。不需要工具。

Edit

檔案與意圖都已明確的有限變更。

Agent

需要探索、命令與驗證的多檔案工作。

Ask 模式能回答的問題，不要使用 Agent 模式。

6. 依任務分配模型

  • 日常工作先用 Auto。
  • 查詢、語法與小型機械式編輯使用輕量模型。
  • 規劃、架構與困難除錯使用強推理模型。
  • 計畫涵蓋困難決策之後，改用較便宜的執行模型。

在長時間工作前先選好推理強度。若任務改變，請以簡潔的交接內容重新評估。

7. 先規劃，再以全新對話執行

記錄驗收條件、可能涉及的檔案、風險與驗證方式。只帶著該交接內容開始執行。

8. 讓 MCP 基準維持精簡

  • 載入的工具定義會增加上下文；主機可能會延遲載入未使用的結構描述。
  • 停用此儲存庫或任務不需要的伺服器與擴充功能。
  • 針對重複性的工作流程，使用乾淨的設定檔或聚焦的 Agent。
  • 在 Copilot CLI 中執行 /context，查看載入了哪些內容。

9. 一次性壓縮 Shell 輸出

RTK

針對常見開發人員命令輸出的編譯式預設值。

snip

YAML 管線與本機節省量追蹤。

每個命令路徑只選擇一層篩選器。預設不要同時疊加兩者。

10. 重複使用程式碼庫地圖

Graphify 會建立可重複使用的儲存庫地圖，供結構化查詢使用。重構後請更新它。

graphify query "驗證中介軟體在哪裡？"
graphify path "Router" "Database"

最適合大型儲存庫與重複的 Agent 工作階段。小型的一次性變更則不必使用。

11. 讓 Token 用量可見

工作階段內

使用 /context 檢查 Copilot CLI 的上下文壓力與已載入的工具。

跨工作階段

Tokentop 會顯示本機即時的 Token、成本、燃燒速率與預算警示。

用這些工具找出浪費；兩者都不會壓縮上下文。

12. 設定穩定的工作階段配置

模型 + 強度 + 模式 + Agent + 技能 + MCP 工具 + 輸出篩選器 + 儲存庫指示

在長時間工作前先選好這些設定。若需要變更，請以相關上下文開啟新的工作階段。

13. 完成前先驗證

  1. 明確列出驗收條件。
  2. 執行目標測試、建構或檢查。
  3. 回報證據，而不是籠統的「完成了」。

在審查發現遺漏之前，先自行檢查結果。

14. 採用並持續落實

冗長的回應

設定精簡輸出的偏好。

龐大的上下文

精簡已載入的指示、檔案與工具。

雜訊多的命令

嘗試一種輸出篩選器；保留診斷資訊。

反覆重工

釐清任務、模型選擇與驗證方式。

針對觀察到的浪費選擇改變項目。比較被接受的成果與總成本。
